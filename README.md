# 社区超市销售管理系统 · 管理端前端

中小型社区超市销售管理系统管理端，依据《超市管理系统_管理端UI》原型实现。

## 技术栈

| 类别 | 选型 |
| --- | --- |
| 框架 | Vue 3.5（Composition API + `<script setup>`） |
| 语言 | TypeScript 5.7（strict 模式） |
| UI 组件库 | Element Plus 2.9（中文语言包，全量图标注册） |
| 构建工具 | Vite 6 |
| 路由 | Vue Router 4（History 模式 + 登录守卫） |
| 状态管理 | Pinia 2 |
| 图表 | ECharts 5 |
| 后端 | Django 4.x + MySQL（当前前端独立运行，数据为本地 Mock） |

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器（默认 http://127.0.0.1:5173）
npm run dev

# 3. 生产构建（含 TypeScript 类型检查）
npm run build

# 4. 本地预览构建产物
npm run preview

# 仅做类型检查
npm run type-check
```

## 已实现功能

1. **登录与鉴权**：账号密码校验、会话持久化（localStorage）、未登录访问自动跳转登录页、已登录访问登录页自动进入看板。
2. **经营看板**：4 项核心指标卡、近 7 日销售额趋势（柱状图）、热销商品 Top 5、库存预警清单、品类销售占比。
3. **商品管理**：商品列表（关键词 / 分类 / 状态筛选 + 前端分页）、分类维护、商品建档表单（含扫码入口、成本价校验）、价签打印（多选 + 价签预览）。
4. **库存管理**：库存查询、库存流水（6 种变动类型标识）、库存预警（含建议补货量）、盘点单管理、库存调整弹窗（含原因必填校验）。
5. **采购管理**：采购订单（多状态流转标识）、到货入库（待入库订单列表）、供应商档案、采购记录、新建采购订单弹窗（含商品明细行内编辑）。
6. **销售收银**：交易流水（含挂单中 / 已退货 / 已作废状态）、退货受理（调出原单、可退数量约束、应退金额实时计算）、挂单管理、交班对账（长短款展示）。
7. **会员管理**：会员档案（等级 / 状态标签、手机号脱敏）、储值管理（资金流水 + 充值弹窗）、积分管理（积分流水）、会员消费分析（等级分布饼图 + 消费排行）。
8. **促销管理**：活动列表（多类型多状态）、新建活动（按活动类型动态展示参数，含时间区间校验）、促销效果对比（活动前后销量双柱图）、优惠券模板。
9. **统计报表**：周期筛选、维度切换（日 / 周 / 月）、销售额走势、销售排行、滞销商品清单、品类占比。
10. **系统管理**：用户管理（多角色）、角色权限（角色列表 + 权限矩阵勾选，含全选 / 半选）、操作日志、参数配置（按分组表单，含开关 / 数字 / 文本多类型）。
11. **角色权限控制**：侧边栏按角色过滤菜单；直接输入 URL 访问未授权功能会被路由守卫拦截并提示（对应验收标准 AC-03）。
12. **登录安全**：连续 5 次密码错误锁定账号 15 分钟，并提示剩余尝试次数（对应 FR-SYS-01 业务规则）。

## 演示数据说明

`src/utils/mock.ts` 是**唯一数据源**，所有页面共用同一份数据集，遵循以下约定：

1. 每个数据集使用独立种子的随机数生成器，且只生成一次并缓存 —— 任意页面、任意时刻调用同一函数，
   结果完全一致（不会出现「商品管理页库存 220、库存管理页库存 131」）。
2. `xxxList(count)` 返回同一基础数据集的前缀切片，`count` 只决定截取长度。
3. 统计卡数字一律由数据集推导（`productStats()` / `tradeStats()` 等），保证「卡片数字」与「列表内容」对得上。
4. 报表页采用近 30 天口径，卡片数字由 `dailyTrend(30)` 求和得出，与趋势图同源。

## 设计规范

样式变量集中在 `src/styles/index.css` 的 `:root` 中，取自原型《03_设计规范》：

- 主色 `--brand-7: #1565C0`，并覆盖 Element Plus 的 `--el-color-primary` 系列
- 成功 `#2ba471` / 警告 `#e37318` / 危险 `#d54941`
- 侧边栏深色 `#0f2544`，页面底色 `#f2f4f8`
- 圆角：小 4px / 中 8px / 大 12px；卡片内边距 20px

## 与后端对接说明

当前 `src/utils/mock.ts` 提供全部演示数据。接入 Django 后端时：

1. 新增 `src/api/` 目录与 `src/utils/request.ts`（基于 axios 或 fetch 封装，统一携带 Token 与错误提示）；
2. 将各视图中来自 `@/utils/mock` 的调用替换为 API 请求，并用 `ref` / `reactive` 承接异步结果；
3. 登录逻辑由 `stores/user.ts` 的本地校验改为调用 `/api/auth/login`，Token 写入 localStorage 并在请求头携带；
4. 侧边栏菜单已按角色过滤（`router/index.ts` 的 `MENU_GROUPS` 带 `roles` 字段），
   接通后端后改为按接口返回的权限集合渲染即可。
